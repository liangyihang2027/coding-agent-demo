claude-mini 架构与今日学习复盘

项目目标是从零复刻 Claude Code 单 Agent 的工程内核。当前主线已经跑通本地 ReAct loop， 并开始把权限审批、CLI 事件映射和 runner 抽象做成可扩展结构。

TypeScript Agent 内核
运行链路
1. 启动 pnpm dev -> src/cli/index.ts
2. 组装 loadConfig -> createRunner -> ConversationState
3. 交互 CodexLikeApp -> runner.run(state, input, events)
4. 推理 AgentLoop.callModel -> LLM stream -> text/tool_calls
5. 工具 PermissionGate -> ToolRegistry.run -> ToolResult
6. 回填 state.addToolResult -> 下一轮模型推理
今天最重要的架构突破

你把“工具能执行”升级成了“工具执行前有风险分级和人工确认”，并且让 UI 可以通过 onPermissionPrompt 接管确认流程。这是从 demo 走向真实 coding agent 的关键一步。

当前边界

CursorAgentAdapter 当前只是把 Cursor SDK 事件映射到 UI，权限闸门主要接在本地 AgentLoop。真正强沙箱和上下文管理仍是后续核心模块。

模块职责

模块 代表文件 核心职责
CLI src/cli/index.ts, src/cli/codex-ui.ts 加载配置、创建 runner、渲染 Ink TUI、消费 AgentEvents
Runner 抽象 src/agent/runner.ts 统一 OpenAI 本地 loop 与 Cursor SDK adapter 的 run/close 协议
Agent Loop src/agent/loop.ts ReAct 迭代：模型流式输出、工具调用、权限确认、结果回填、step 上限
LLM Client src/llm/client.ts OpenAI 兼容流式协议，把文本 delta 和 tool_calls 汇总成内部事件
Tool Registry src/tools/registry.ts 工具唯一注册、zod 参数校验、JSON Schema 暴露、错误结果回填
Permission Gate src/permission/* 按工具和命令内容分级，低风险自动放行，中高风险确认后执行
Sandbox src/sandbox/index.ts 目前是最小 spawn 封装，后续要补进程树、超时、截断和危险命令拦截

今天学到的东西

  1. 1 Agent 工程不是单个 LLM 调用，而是一套事件驱动的运行时：状态、工具、权限、UI 都围绕统一协议协作。
  2. 2 工具调用要先作为 assistant 消息写入历史，再把 tool result 回填，这样模型下一轮才能基于真实执行结果继续推理。
  3. 3 权限闸门最好插在工具执行前，而不是散落在每个工具内部；这样风险策略、UI 确认和测试都能独立演进。
  4. 4 CLI UI 不能直接理解 provider 细节，应该消费统一 AgentEvents；这让 OpenAI loop 和 Cursor SDK adapter 可以共用同一套界面。
  5. 5 测试的价值在于锁住最容易回归的行为：例如拒绝高风险工具时不执行工具，但仍回填拒绝结果给模型。
